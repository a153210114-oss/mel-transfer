# 华伴 V1.1 参考截图映射

本文用于固定 V1.1 的页面与功能设计依据，避免截图上下文丢失。华伴不复制微信或小红书品牌与视觉，只继承成熟交互习惯，并叠加华伴 AI、本地城市关系网、身份码、推荐关系和积分权益。

## 总原则

华伴 V1.1 = 微信式通讯关系 + 小红书式本地内容流 + 华伴 AI 执行能力。

内部理解：华伴采众人之长，补用户之需。该句只作为产品设计判断，不作为对外宣传文案。

对外表达：华伴是一款内置 AI 的 App，帮助用户从海量信息中挣脱，重新专注自己的本地生活。

微信和小红书更与国内内容、关系和平台生态相关；华伴要与本地相连、与世界相通。

## 参考边界

所有功能键和页面都按成熟产品的用户习惯参考，但华伴不照搬任何一个产品。

### 微信负责的部分

微信只作为通讯、好友关系和工具入口参考：

- 消息列表
- 好友聊天
- 群聊
- 通讯录
- 添加好友
- 扫一扫
- 二维码名片
- 好友资料
- 好友备注、标签、权限
- 聊天加号面板
- 设置、拉黑、投诉、删除联系人

### 小红书负责的部分

小红书替代微信的朋友圈和视频号，作为内容、动态、主页和市集参考：

- 首页内容流
- 关注 / 发现 / 附近
- 双列瀑布流
- 图文动态
- 视频动态
- 个人主页
- 笔记、评论、收藏、赞过
- 发布入口
- 写想法
- 市集
- 消息里的赞藏、关注、评论和 @ 通知

### 华伴自己的部分

华伴不是再做一个微信或小红书。华伴在每个环节增加 AI 协助者：

- 首页：AI 搜索附近内容、推荐本地人和名片。
- 发布：AI 整理文字、生成标题、补标签、判断城市和类型。
- 动态详情：AI 总结内容、判断是否值得联系作者。
- 作者主页：AI 总结这个人是谁、能提供什么、适合谁联系。
- 好友关系：AI 帮用户记录来源、备注、标签和关系背景。
- 聊天：AI 总结聊天、提取待办、生成回复、整理时间地点。
- 市集：AI 根据一句话筛选本地服务、商品、活动和卡券。
- 消息：AI 帮用户区分重要未读、好友申请和互动通知。
- 我的：AI 解释积分、等级、权益和资料完善建议。

### 轻代码 / 无代码 + AI 自动化

华伴最能体现价值的地方，不是让普通用户写代码，而是让用户用轻代码、无代码和 AI 自动化运行自己的本地业务与关系网络。

- 用户通过表单、对话、模板和授权连接配置自己的名片、小店、服务、活动、卡券和 API。
- AI 负责理解资料、生成介绍、补全字段、分类标签、推荐对象、提醒跟进和运营复盘。
- 小店和服务者后台优先做可视化配置，不要求用户理解数据库、接口、脚本或自动化流程。
- 高级用户或商家可以接入自有 API，但必须以授权、可撤销、可审计的方式配置。
- 运营后台应支持低代码 / 无代码管理：内容审核、用户管理、积分审核、城市运营、活动配置、自动化任务和日报。
- n8n 等自动化只作为后台执行层，用户侧只看到结果、提醒、建议和下一步。

### 替代关系

```text
微信朋友圈 / 视频号
→ 在华伴中由小红书式动态、视频、主页和内容流替代

微信聊天 / 通讯录 / 扫一扫 / 二维码
→ 在华伴中保留为通讯和关系基础

传统搜索 / 手动筛选 / 手动整理
→ 在华伴中由 AI 参与协助
```

第一阶段只做：

- 附近动态
- 作者名片
- 我的二维码名片
- 添加好友 / 关注 / 收藏 / 备注
- 好友聊天
- 本地市集入口
- 消息与互动通知
- 积分权益
- AI 整理、搜索、推荐和打开功能

第一阶段不做：

- 需求卡片
- 重交易平台
- 订单确认
- 合约履约
- 临时交易会话

### 红框重点

用户截图中红框标注的 `扫一扫` 和 `附近的人` 必须作为 V1.1 的高优先级功能键。

- 这两个入口不能被弱化成后台能力，必须在首页、发现 / 附近、添加好友和 AI 指令里都能到达。

### 华伴改动

### 红框重点

用户截图中红框标注的 `小店与卡包` 必须作为 V1.1 的高优先级个人资产入口。

- `小店`：对应本地服务名片、服务项目、商家号、服务者主页。
- `卡包`：对应服务券、活动券、权益券、积分权益凭证。
- 第一阶段不接支付和重交易，但要保留“展示、收藏、分享、咨询、核销准备”的产品位置。
- `小店` 后续可以接入用户 / 商家的自有 API，例如库存、预约、菜单、报价、订单状态、课程表、车队排班、服务档期等。
- 小店 API 必须由用户授权配置，华伴只做展示、同步、AI 咨询和联系入口，不擅自替商家承诺价格、库存或履约。
- 小店后台优先使用轻代码 / 无代码配置：资料表单、服务模板、价格说明、预约规则、常见问题、自动回复、API 授权和自动化任务。
- AI 可以自动生成小店介绍、服务分类、FAQ、推广文案、客户回复和运营建议。
- `小店与卡包` 要和积分权益、推荐关系、好友聊天、市集入口联动。

### 华伴改动

- `小店与卡包` 对应本地服务名片、活动券、服务券、积分权益。
- `我` 页必须展示二维码名片和积分权益。

- `文字生图`：进入文字生成图片入口，避免和动态配文混淆；适合把想法、服务介绍、活动或资源分享转成图片动态。
- 后续可在进入发布编辑页后再选择类型，不在第一层动作表放太多选项。
- AI 在第二步出现，帮助整理标题、正文、标签、城市和可见范围。

## 华伴底部主导航

综合微信和小红书，V1.1 使用：

```text
首页 / 市集 / + / 动态 / 我
```

### 首页

首页是对话中心，不是动态流。

- 顶部保持华伴 AI 首页气质：左上角菜单、中间华伴 AI、右上角 AI 入口。
- 中间保留大留白、华伴 AI 形象、问候语。
- 未读消息是可移动浮窗。
- 消息列表也在首页：用户与用户对话、用户与 AI 对话都从首页切换。
- 底部 AI 对话框常驻：声波、文字输入、语音转文字、`+` 功能菜单、发送。

### 市集

本地服务、商品、活动、卡券，第一阶段只做展示和联系，不做重交易。

### 发布

中间 `+`，打开发布面板：

- 写想法
- 发图片
- 发视频
- 发求助
- 发服务
- 发活动
- 发资源

### 动态

动态放在底部第四个入口，也就是原来“消息”的位置。

- 动态进入后是独立滚屏长页面。
- 页眉中间只写“动态”，左侧返回首页，右侧 `...` 打开与动态相关的动作菜单。
- 动态内容参考小红书式本地内容流，替代微信朋友圈和视频号。
- 动态页只保留内容、头像、图片/视频预览和四个动作图标：转发、赞、关注、收藏。
- 用户头像出现的地方，点击进入该用户个人资料全屏页。

### 我

二维码名片、个人资料、积分权益、收藏、动态、店铺、卡包、设置。

## 必须沉淀到数据里的关系字段

- `source`：扫码、附近动态、搜索、群聊、AI 推荐、分享名片、市集、活动。
- `tags`：用户给好友打的标签。
- `note`：备注。
- `permission`：朋友圈 / 动态 / 聊天 / 名片权限。
- `favorite`：星标。
- `blocked`：黑名单。
- `recommendable`：是否允许被推荐给其他用户。
- `recommendation_reason`：用户或 AI 生成的推荐理由。
- `recommended_by`：由谁推荐。
- `recommended_to`：推荐给谁或哪个群。
- `first_seen_at`：第一次看到对方。
- `added_at`：添加好友时间。
- `mutual_groups`：共同群聊。
- `profile_view_count`：名片访问次数。

## AI 在这些页面里的角色

- 在首页：搜索附近内容、解释动态、推荐相关名片。
- 在发布页：整理配文、生成标题、选择分类、补标签。
- 在名片页：总结这个人能提供什么、推荐是否联系。
- 在好友资料页：根据用户备注和标签，判断是否适合推荐给其他用户。
- 在聊天页：总结聊天、生成回复、整理待办、提取联系方式，并可把合适的好友名片推荐给对方。
- 在市集页：根据需求筛选服务、商品和活动。
- 在消息页：区分未读优先级、提醒重要好友申请。
- 在我页：解释积分、等级、权益和下一步完善项。
