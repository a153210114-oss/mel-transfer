# 华伴 V1.1 页面功能与按键逻辑表

更新日期：2026-07-28

本文件定义每个页面的功能、入口、按键作用、跳转去向和闭环条件。页面设计和开发必须遵守：用户点任何按键，都要知道为什么会到下一个页面，以及在那里要完成什么。

详细逐页闭环验收以 `docs/PAGE_CLOSURE_MAP.md` 为准：那里记录每个页面、弹层、按键的“点了去哪、下一步做什么、成功/失败如何处理”。

## 页面类型

| 类型 | 说明 | 例子 |
| --- | --- | --- |
| 主页面 | 底部导航和左侧菜单可直接进入的一级页面。 | 首页、市集、动态、我 |
| 全屏流程页 | 从主页面或菜单进入，完成一个明确任务。 | 添加朋友、编辑动态、位置、积分权益 |
| 系统能力页 | 调用手机系统能力或浏览器权限。 | 相册、拍摄、文件、定位 |
| AI 执行页 | 用户通过输入框或语音发指令，由 AI 转成动作。 | 华伴 AI 对话、AI 整理、AI 搜索 |
| 临时弹层 | 只用于选择下一步，不承载复杂说明。 | 发布来源、分享目标、可见范围 |

## 全局原则

- 首页是对话和消息中心，不承担动态信息流。
- 动态是独立滚屏页面，从底部动态、菜单动态、AI 指令“打开动态”进入；这里用于看其他用户动态。
- 发布动态只从动态页右上角 `+` 进入，避免和手机浏览器自带 `+`、底部导航混淆。
- 输入框 `+` 是当前对话的附件和工具入口，只负责当前会话里的动作。
- 左上菜单是高频和可排序入口，不解释功能细节。
- 每个头像都打开用户个人资料全屏页；点对方头像查看对方资料和添加日期，点自己头像进入自己的资料编辑页，可再次编辑并保存。
- 任何没有后端闭环的功能，页面可以预留，但不能给“已完成”反馈。
- 积分只能在动作完成、接口确认后发放；不能在用户刚点击时发放。

## 待修正的已知问题

| 问题 | 原因 | 修正方向 |
| --- | --- | --- |
| 有些按钮只弹 toast | 没有明确路由/动作处理 | 改为真实页面、系统选择器或明确“未接入”状态 |
| `operationPage` 过于泛用 | 把多个流程都做成说明列表 | 只保留临时选择，不承载主流程 |
| 发布成功后礼花可能早于真实入账 | 前端以发布成功代表积分完成 | 改为积分接口确认后再礼花 |
| 文件选择只是本地预览 | 未接对象存储 | 媒体上传表和对象存储接入后再升 L4/L5 |
| 二级推广积分未确认落地 | 缺真实推荐关系和积分流水验证 | 必须查表验证，不许口头确认 |
