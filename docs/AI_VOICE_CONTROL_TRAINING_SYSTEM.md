# 华伴 AI 语音操控训练系统

更新日期：2026-07-28

本文件定义华伴 AI 的“语音/文字操控训练系统”。它不是单纯语音识别，而是把用户一句话变成华伴内部可执行动作。

## 1. 目标

用户可以用自然语言控制华伴：

- 单一功能操作提示词：覆盖华伴全部功能键。
- 固定提示词到多表达训练：同一个功能支持“打开、点击、调用、进入、帮我看、给我调出”等不同说法。
- 语义理解训练：用户不用说按钮名，AI 也能理解目标。
- 多动作提示词：串联多个内部功能。
- 生成类任务：调用模型生成文案、图片、视频、表单、服务卡和自动化草稿。
- AI 代执行：用户明确授权后，AI 可以代替点击确认、保存、发送、发布等最后动作。
- 分档订阅：生成、复杂执行、小店 API 和自动化能力按订阅档位与插件额度开放。

最终能力：

```text
用户一句话 → 意图识别 → 语义补全 → 动作拆解 → 订阅/插件检查 → 权限/安全检查 → 执行 → 反馈 → 学习沉淀
```

## 2. 四层训练结构

### L0 功能键全覆盖

先建立华伴内部功能键目录。凡是用户能点的按钮、菜单、入口、开关、表单提交、发布确认，都要有唯一 `action_key`。

覆盖范围：

- 首页：菜单、AI 入口、未读消息、用户会话、AI 会话、底部输入框、声波、麦克风、加号、发送。
- 底部导航：首页、市集、发布、动态、我。
- 左侧菜单：发起群聊、添加朋友、扫一扫、收付款、首页、通讯录、动态、我。
- 聊天页：文字输入、语音输入、图片、相机、语音通话、视频通话、位置、文件、转发、AI 切换。
- 通讯录：搜索、添加朋友、联系人目录、备注、标签、推荐给朋友、权限、黑名单、星标。
- 动态：发布、转发、赞、关注、收藏、举报、筛选、附近的人、可见范围。
- 市集/小店：搜索、服务卡、卡包、API 授权、表单、优惠券、自动化日志。
- 我的：二维码名片、积分权益、定制 AI、头像、设置、隐私与内容安全。
- 后台：用户、动态、审核、AI Prompt、n8n、积分、官网、巡检。

每个功能键都要记录：

```json
{
  "actionKey": "call_contact_voice",
  "displayName": "语音通话",
  "page": "contact_profile",
  "requiredSlots": ["target_user"],
  "safetyLevel": "confirm",
  "canonicalPhrases": ["给联系人打语音", "拨打语音通话"],
  "aliases": ["跟他说话", "打给他", "语音一下", "我要通话"]
}
```

### L1 简单提示词

用户说一个明确命令，AI 调用单一功能。

训练要求：

- 每个功能键至少有 1 条固定口令。
- 每个常用功能至少有 10 条口语表达。
- 训练表达要覆盖“打开、点击、进入、调用、调出、帮我看、我要用、给我弄出来”等动词。

示例：

| 用户说 | 意图 | 动作 |
| --- | --- | --- |
| 打开动态 | `open_dynamic` | 打开动态页 |
| 发动态 | `open_publish` | 打开发动态面板 |
| 找附近的人 | `open_nearby_people` | 打开附近的人 |
| 打开市集 | `open_market` | 打开市集 |
| 看积分 | `open_growth` | 打开积分权益 |
| 问华伴 AI | `open_ai_chat` | 打开 AI 对话 |
| 扫一扫 | `open_scan` | 打开扫码页 |
| 调出二维码 | `open_my_qr_card` | 打开我的二维码名片 |
| 点语音 | `switch_voice_input` | 切换语音输入 |
| 叫出相册 | `open_album_picker` | 打开相册 |

### L2 多个提示词

用户连续说多个目标，AI 按顺序组合多个功能。

示例：

| 用户说 | 动作计划 |
| --- | --- |
| 帮我找 Carlton 附近会中文的人，适合喝咖啡的 | 搜索动态 → 筛选城市/兴趣 → 推荐名片 → 打开推荐列表 |
| 把这个人推荐给 Mia，再帮我写一句介绍 | 打开名片 → 检查可推荐状态 → 生成介绍语 → 打开转发给朋友 |
| 我想发一个周末活动，帮我整理一下 | 打开发动态 → 生成标题/正文/标签 → 安全预检 → 进入发布确认 |
| 帮我看看今天有什么未读，重要的先说 | 打开首页消息 → 读取未读摘要 → 区分好友/系统/AI 提醒 → 口语总结 |
| 打开通讯录，找到 Owen，拨打语音通话 | 打开通讯录 → 搜索 Owen → 确认联系人 → 发起语音通话 |

### L3 提示词 + 语义理解

用户说的是目标，不是明确按钮。AI 需要理解上下文、补全缺失信息、拆成任务。

示例：

| 用户说 | AI 理解 | 计划 |
| --- | --- | --- |
| 我想认识几个本地靠谱的人 | 本地关系匹配 | 询问城市/兴趣或使用当前城市 → 搜索名片/动态 → 排序推荐 |
| 我要跟 Owen 通话 | 联系人语音通话 | 识别 Owen 为联系人 → 检查重名 → 打开确认 → 发起语音通话 |
| 帮我做个招募咖啡局的内容 | 图文动态生成 | 生成标题、正文、标签、时间地点问题 → 发布前预检 |
| 给我的小店做一个报名表 | 表单制作 | 选择表单模板 → 生成字段 → 预览 → 保存到小店 |
| 帮我做一条短视频介绍这个服务 | 视频生成任务 | 提取服务卖点 → 生成脚本 → 生成分镜 → 进入视频生成/待审核 |
| 帮我把这个 API 接到小店里 | 自动化配置 | 读取授权状态 → 字段映射草稿 → n8n 工作流草稿 → 后台审核 |

### L4 生成类模型操控

生成类功能需要接入模型，不是简单按钮映射。

生成类功能也要按 AI 执行能力分档：

- 免费版：基础对话、简单草稿、低频试用。
- 增强版：多步骤语义执行、连续语音修改、关系/动态摘要。
- 创作版：图文生成、视频脚本/封面、表单生成。
- 商家版：小店服务卡、优惠券、API 字段映射、线索整理。
- 运营版：内容审核辅助、城市内容整理、自动化运行统计。

对应能力见 `docs/AI_PLUGIN_MONETIZATION.md`。

能力：

- 一句话生成文案。
- 一句话生成图片。
- 一句话生成视频脚本、分镜和封面。
- 一句话生成表单。
- 一句话生成服务卡、小店介绍、优惠券说明。
- 语音指令继续修改生成结果。
- 结合按钮或语音确认完成保存、发送、发布。

示例：

```text
用户：帮我做一条墨尔本周末咖啡局动态。
AI：生成标题、正文、标签、图片建议。
用户：轻松一点，别太像广告。
AI：改写。
用户：可以，发出去。
AI：执行发布确认，记录“用户语音确认，AI 代执行”。
```

## 3. 动作类型

华伴内部统一动作类型：

| 类型 | 说明 |
| --- | --- |
| `single_action` | 单一功能，例如打开页面、搜索、扫码 |
| `multi_step_action` | 多步骤功能，例如发布动态、推荐名片 |
| `semantic_task` | 语义任务，例如找人、做表单、生成内容 |
| `creative_generation` | 图文、视频、标题、脚本、海报、活动文案 |
| `form_builder` | 表单、报名页、服务卡、小店资料 |
| `automation_builder` | API 字段映射、n8n 工作流、自动回复 |
| `review_required_action` | 需要内容审核、权限确认或人工复核的动作 |

## 5. 槽位与语义补全

AI 需要抽取并补全槽位：

- `city`：城市。
- `geo_scope`：当地、异地、异国、附近。
- `target_user`：目标好友或群。
- `content_type`：文字、图文、视频、表单、服务卡。
- `topic`：主题。
- `publish_scope`：公开、朋友、部分可见。
- `business_object`：小店、卡包、服务、API。
- `risk_context`：成人、儿童、交易、医疗、法律、金融、移民、隐私。

缺槽时处理：

- 低风险可用默认值。
- 中风险要追问一次。
- 高风险必须用户确认或进入后台审核。

## 6. 安全与权限前置

AI 不能无条件执行所有动作，但可以在用户明确授权后代执行最后一步。

AI 执行前必须先检查：

- 当前订阅档位是否允许该能力。
- 对应插件是否已开通。
- 插件额度是否足够。
- 是否需要消耗额度确认。
- 是否需要内容审核。
- 是否需要外部 API 授权。

允许 AI 代执行的条件：

- 用户已经看到或听到即将执行的内容/对象/结果。
- 用户给出明确确认，例如“可以，发出去”“保存吧”“就这样发给 Owen”“确认发布”。
- 操作不涉及被拦截内容、未成年人风险、未授权 API、支付、积分冲正或后台强审核。
- 系统记录确认方式、确认原文、执行动作、时间、对象和结果。

不能默认代执行的情况：

- 用户只表达模糊目标，例如“帮我处理一下”“你看着办”。
- 联系人存在重名或对象不确定。
- 发布内容未展示给用户。
- 涉及高风险内容、安全审核、外部 API 授权、支付、积分入账或账号限制。

必须确认的动作：

- 发布公开动态。
- 发给朋友或群。
- 添加好友、推荐名片。
- 修改公开头像、AI 形象、资料。
- 小店/API 授权。
- n8n 自动化启用、暂停、恢复。
- 积分入账、冻结、冲正。
- 成人敏感内容打开。

确认方式可以是按钮，也可以是语音或文字。关键不是一定点按钮，而是必须有明确确认。

必须审核的动作：

- 图文/视频公开发布。
- 服务卡、小店介绍、优惠券、价格、资质。
- 可能涉及成人、未成年人、高风险服务、侵权、虚假承诺、刷分的内容。
- AI 生成的公开图片、视频、头像和海报。

## 7. 学习机制

华伴的“学习”不是无限吸收用户隐私，而是沉淀可审核的操作样本。

可学习：

- 用户常用说法与标准意图的映射。
- 同义词：发动态/写想法/发一下/帮我说。
- 用户确认后的动作计划。
- 用户修改后的文案偏好。
- 失败案例与纠错记录。

不可学习：

- 未授权的聊天原文。
- 敏感个人信息。
- 未成年人风险内容。
- 被拒绝、移除、申诉失败的违规内容作为正样本。

学习数据必须脱敏、摘要化、可撤回、可审计。

## 9. 典型能力路线

第一阶段：

- 单功能打开。
- 搜索动态、名片、市集。
- 发布动态草稿。
- 推荐名片。
- 积分解释。

第二阶段：

- 多步骤任务计划。
- 图文生成。
- 表单制作。
- 小店服务卡生成。
- 自动化配置草稿。

第三阶段：

- 视频脚本和分镜。
- 多模态生成任务。
- n8n 工作流自动草拟。
- 用户个性化偏好学习。
- 后台透明评估和训练样本回放。

## 10. 后台管理要求

后台必须能看到：

- 意图库。
- 提示词样本。
- 同义词和口语表达。
- 执行动作映射。
- 成功率、失败率、人工接管率。
- 用户确认率。
- 内容安全拦截率。
- 每次模型输出与最终执行动作。

所有 Prompt、意图、动作计划都必须可更新、可暂停、可回滚。
