# 华伴版本更新与功能展示机制

更新日期：2026-07-28

本文件定义华伴未来向用户介绍新功能、展示视频、并让用户选择版本更新的机制。

## 1. 基本原则

华伴的版本更新不只靠系统强推。重要功能上线前，先通过消息和视频让用户理解，再让用户选择是否体验或切换。

原则：

- 基础安全、合规、修复类更新可以强制。
- 体验变化、AI 新能力、收费插件、界面大改版，优先让用户选择。
- 新功能用短视频、图文说明和 AI 口语解释展示，不堆复杂说明。
- 用户选择必须可记录、可撤回、可灰度。

## 2. 更新类型

| 类型 | 说明 | 用户选择 |
| --- | --- | --- |
| `security_patch` | 安全、隐私、合规、漏洞修复 | 可强制 |
| `feature_preview` | 新功能预览，例如 AI 生成、表单、小店 API | 可选择体验 |
| `ui_refresh` | 首页、动态、菜单等体验调整 | 可选择切换 |
| `paid_plugin` | 收费插件或订阅档位上线 | 必须明确确认 |
| `workflow_upgrade` | n8n 自动化、API 授权流程升级 | 需要授权确认 |
| `deprecated_version` | 旧版本即将停止维护 | 提前通知并引导迁移 |

## 3. 触达方式

版本更新通过三类入口触达：

1. 首页消息列表：出现“华伴更新”或“功能预览”系统消息。
2. AI 对话：用户问“有什么新功能”时，AI 用口语解释。
3. 设置页：保留“版本更新”入口，展示当前版本、可体验版本和更新记录。

消息不做强广告。文案保持轻：

```text
华伴有一个新能力可以试用：用一句话生成表单。你可以先看 30 秒演示，再决定是否开启。
```

## 4. 视频展示

新功能优先用短视频展示：

- 15 到 45 秒。
- 只展示一个核心场景。
- 用户看完后可点“体验新版”“稍后再说”“保持当前版本”。
- 视频下方只放关键动作，不放长说明。

视频可以绑定：

- 版本号。
- 功能 key。
- 插件 key。
- 订阅档位。
- 适用城市/人群。
- 是否需要确认收费或授权。

## 5. 用户选择

用户可以选择：

- `try_now`：立即体验新功能或新版。
- `keep_current`：保持当前版本。
- `remind_later`：稍后提醒。
- `enable_plugin`：开通插件或试用额度。
- `rollback`：从新版回到旧体验。

所有选择要写入版本选择记录，用于灰度、回滚和客服解释。

## 6. AI 解释口径

AI 介绍版本更新时要说人话：

```text
这次更新主要是让你少点按钮。比如你可以直接说“帮我做一个周末咖啡局报名表”，华伴会生成表单草稿。你可以先试用，不想用也可以保持现在的版本。
```

AI 不应说：

- “必须升级才能继续使用”除非是安全或合规强制更新。
- “开通后一定带来收益”。
- “付费插件能增加积分或分配权益”。

## 7. 后台要求

后台需要管理：

- 版本发布计划。
- 新功能说明。
- 展示视频。
- 面向用户范围。
- 强制/可选策略。
- 用户选择记录。
- 版本灰度比例。
- 回滚状态。
- 消息送达、打开、观看和选择数据。

## 8. 与插件订阅的关系

收费插件上线时，版本更新消息只能说明功能和试用方式，不能默认扣费。

AI 执行收费能力前仍然必须经过：

1. 订阅/插件检查。
2. 额度预览。
3. 用户确认。
4. 内容审核。
5. 外部 API 授权。

版本更新负责“让用户知道和选择”，插件系统负责“确认权益和额度”。
